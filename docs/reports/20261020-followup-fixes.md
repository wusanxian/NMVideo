# 后续检查问题修复记录

日期：2026-10-20。对应 [后续改进检查](20261020-followup-review.md) 的 6 项已复现问题。

## 实现

| 检查项 | 已修改行为 | 验证重点 |
|---|---|---|
| W1 取消后镜头锁住 | 数据库单事务取消任务并释放仍属于该任务的镜头；不清理新任务的绑定；已取消任务不能被 worker 重新认领。待恢复任务入队后取消也会完成状态收尾 | 取消→再次生成成功；重复取消；旧任务不影响新占用；运行中先停止再删除 |
| C1 ComfyUI 地址不一致 | jobs 新增兼容迁移字段 comfy_url，准备时固定服务；缓存按引擎与地址区分；上传、提交、等待、下载、恢复、冻结图片重传及原生预览升级均沿用原服务 | A/B 服务混合排队后再切 C，任务仍各自在 A/B 执行；恢复探测与升级保留原地址 |
| C2 导出丢失原声 | 探测冻结视频的音轨，按源视频入点及时间线起点加入混音；无原声片段保持静音，可与对白、音乐、音效共存 | 真实 MP4 原声导出、裁剪后频率、静音段落位和多源声音保留 |
| W2 音乐改变成片长度 | 混音按时间线长度裁剪和有限补静音；最终封装按视频时长限制；音轨出点按素材绝对位置解释 | 短音乐不截短视频，长音乐与超时字幕不延长成片；音轨裁剪、延迟落位 |
| W3 删除音轨破坏共享文件 | 对白及音乐/音效轨只移除数据库引用，不随轨道删除物理文件 | 跨项目、多条目、不同轨道类型共享音频仍可使用 |
| W4 恢复分页漏任务 | 以 created_at + 唯一 id 稳定排序，恢复扫描使用游标，替换会随状态过滤结果缩小而跳行的 OFFSET | 超过两页 running / needs_attention 全部处理；同一时间戳、升降序和边处理边改变状态 |

真实音视频回归还修复了两个关联问题：裁剪后的 adelay 前导静音缺 PTS 时按样本重建时间戳；分段缩放/帧率转换在尾部补一帧并按输出时长截断，避免每段少一帧造成累计偏移。

## 使用边界

- 用户尚未安装 ComfyUI/FreeVideo；本轮完成代码接入与协议验证，模型实际出片、GPU 行为、FreeVideo 缓存仍待实机验收。
- 旧任务没有原服务地址可追溯时，只能在首次执行/恢复时采用当前设置并固定；无法从历史数据推断曾经使用的地址。
- 原生预览二采依赖原服务保留缓存，更改全局设置不会迁移缓存或切换该任务的执行服务。
- 删除音轨保留磁盘文件是本轮的保守策略。后续单独增加资产引用索引、占用统计和可预览的回收流程。
- 本轮沿用现有 UI，原声音量/静音控制仍属时间线后续功能。
