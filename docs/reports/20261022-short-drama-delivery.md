# 0.1.2 短剧出片与 Windows 交付

日期：2026-10-22。实施范围是前次检查建议的第一批：对白完整性、字幕时序、竖屏导出、当前代码的 Windows 安装包。保留工作区原有 db.py、novel_shots.py、storyboard.py、test_novel_shot_plan.py 修改，未提交或推送代码。

## 行为变化

- 同镜头配音按创建顺序逐句播放，不再从镜头起点同时混合。镜头编辑器支持选择说话人，使用角色绑定音色，也可手动选音色。每次添加一条对白；重录后需要删除不用的旧条目。
- 默认保留完整对白：对白总时长超过画面时延长剪出点末帧，后续镜头随之顺延。关闭导出页自动延长选项时明确拒绝超时导出，不再静默裁掉对白。音乐、音效仍按各自绝对起点播放。
- 原声音轨遵守视频剪入/剪出范围；延长的部分不读取原视频被剪掉的声音或画面。
- 自动字幕优先使用实际配音文本和时长。每条配音内部按标点分句、按字符比例分配时长；无配音镜头仍可从对白生成字幕。不是 ASR/逐字强制对齐，修改配音/裁切后应重新生成并检查字幕。
- 导出画布支持跟随首镜头、1080×1920、1920×1080、1080×1080；可完整留边或居中裁切。界面默认选择竖屏，API 保持默认跟随来源，兼容已有调用。输出尺寸和裁切选择随导出清单冻结。
- 字幕烧录增加左右与底部边距。输出画布放大不代表生成模型画质提升。
- TTS 超过单条 300 字会提示分句，不再静默截断。

## 实现与兼容性

新增 `dialogue_timing.py` 共享对白排程，供时间线布局、字幕生成和导出混音使用。导出设置存入现有清单 `output` 字段，无新增数据库迁移。

实测 FFmpeg 7 的 trim/tpad 组合导致每片段少一帧；对需要延长的片段改为先物理裁切，再填充末帧。其余片段继续走原单次归一化路径，避免多余转码。滤镜语义参考 [FFmpeg 官方文档](https://ffmpeg.org/ffmpeg-filters.html#tpad)，最终以实际输出帧数、时长和音频采样验收。

旧导出清单可继续读取；没有 `output` 设置的旧清单默认完整保留对白，跟随第一镜头尺寸。旧字幕不会自动重写，应按新配音重新生成。

## 尚未包含

本批没有接入口型同步、克隆音色、ASR 强制对齐或视觉角色一致性检测；也未执行真实模型的完整短剧推理、新机器安装或旧版原地升级。当前实际媒体回归使用合成色块与音频，不能冒充 AI 短剧画面质量验收。
